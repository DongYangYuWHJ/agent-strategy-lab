# 002：采用 OpenCode，保留独立实验层

记录日期：2026-10-21，回顾性补记。状态：已选型，部分落实。

## 背景与决定

用户希望开发者通过对话提出需求，由系统分配执行任务；公司 GIA 也使用 OpenCode。项目选择 OpenCode 作为交互和 Agent 执行基础，同时保留自己的任务、验收、预算与报告约定。

## 已落实的变化

- 固定本地 OpenCode 2.0.32，准备项目配置、角色提示词和启动桥接。
- 初始交互角色为 Sol 协调者与 DeepSeek 执行者，另有 Sol 单 Agent 对照角色。
- 复用现有本地密钥设置，通过子进程环境传递；公共配置只保存占位符。
- 已验证配置与角色加载。

## 尚未落实及实验含义

OpenCode 尚未接入受控任务副本、独立验收和包含主／子会话的完整账本。现有 LiveCodeBench 报告来自原生 runner，不能标为 OpenCode 的实验结果。

这项选择体现执行工具与实验方法分层。后端会影响提示词、工具、缓存、重试和辅助调用，未来必须记录并单独分组；公司 GIA 的版本、配置入口、模型接口和用量获取仍待核实，不能假定本地配置可直接导入。

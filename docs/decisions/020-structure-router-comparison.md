# Plan 20 · 任务路由与架构选择

审查 Router 的试跑遇到了验证瓶颈。现有任务和对照配置下，三组均为 3/3 通过，按需组又全部触发了 Sol 审查，其中一次只由测试引用格式触发。这批数据能说明升级行为和开销，但无法有效检验审查能补救哪些失败，也无法检验 Router 能否识别这些情况。因此先转向任务 Router，研究能否在规划前选择合适的架构，并在不同难度的任务上兼顾通过率和总费用。[Plan19 审查 Router 结果](019-task-and-review-routers.md)

首轮架构对照、两档 Router 试跑和 14 题三组对照均已完成。最终结果见文末。

## Structure Router 首轮对照

Structure Router 已接入批次入口。Luna 在规划前读取原始任务、可编辑路径和简短文件清单，返回一个候选架构 ID、理由和风险。运行器校验 ID，并在同一账本下启动对应流程。路由失败时保留已发生的费用和停止原因。分档标签只进入汇总，LiveCodeBench 描述中的难度标题在路由请求中移除。

候选路径为 Luna 单体、Luna 规划后交给 Luna，以及 Sol 规划后交给 Luna。固定参照组始终采用 Sol 规划后交给 Luna。两组各跑同样八题一次，共十六个位置，配置上限为 5 美元。

| 汇总档位 | 任务 |
|---|---|
| 低 | Geometric Sequence、分页边界 |
| 中 | Gravity、游标分页 |
| 高 | Plan16 的令牌迁移、签名组合、缓存原子更新、缓存组合 |

每次路由决定保存为 `structure-routing.json`。批次报告按档位和组别分别列出通过数、有效验收数、路由费用及整段费用。

## 两档 Router 的选择

首轮 Router 实际只用了两条路径，新加入的三道候选题也都由 Luna 单体通过。因此两档 Router 只保留两个候选架构：

- **低成本档 `luna-solo`**。同一个 Luna 完成规划、实施、自查和修正。
- **强化档 `sol-luna-self-tests`**。Sol 负责规划，同一个 Luna 负责后续实施、自查和修正。

两档 Router 与固定 Luna 单体、固定 Sol 规划加 Luna 自查组成三组对照，使用相同任务、四轮工作流和独立验收。用已通过的候选题观察是否过度升级，优先从已有结果中挑少量两条固定路径表现有差异的题来观察漏升级。主要比较最终通过数和总费用，路由费用计入整段成本，耗时单列。

两档试跑的 7 项新增运行均通过验收。Router 在四道题上全选了 Sol 规划。三道中档题三组均为 3/3 通过，Router 组估算 0.283636 美元，固定 Sol 规划组为 0.278991 美元，相差约 1.7%。固定 Luna 单体为 0.118826 美元。缓存原子更新题的 Router 和固定 Sol 规划都通过，同配置的 Luna 单体记录仍缺失。[两档试跑报告](../../artifacts/plan20-two-tier-router-live-01/comparison.md)

## 14 题混合难度对照

前两轮的任务数量和难度配比限制了对 Router 整体效果的判断。首轮八题里有四道困难题，低、中难度各只有两道。两档试跑则只有三道中档和一道困难题，Router 全部选择 Sol 规划，因此这轮几乎相同的费用主要反映了两组使用同一架构。要衡量日常任务里简单题占多数时的总开销，需要覆盖更多适合 Luna 单体的任务。

因此将任务集扩为 8 道简单、4 道中档、2 道困难。简单题用于观察 Router 是否能选用 Luna 单体，中、困难题用于观察升档选择和通过数。沿用现有题目、两条候选架构和四轮流程。难度标签只用于分组报告，LiveCodeBench 留出集继续保留。

| 难度 | 数量 | 任务 |
|---|---:|---|
| 简单 | 8 | Happy New Year 2025、9x9 Sum、Geometric Sequence、Seek Grid、分页边界、HTTP 重试、超时配置、笔记软删除与恢复 |
| 中档 | 4 | Gravity、TOMLKit 配置往返、Packaging 依赖组错误、TinyDB 快照恢复 |
| 困难 | 2 | Cachetools 缓存原子更新、ItsDangerous 签名策略与迁移组合 |

主对照为两档 Router 和固定 Sol 规划加 Luna 自查，每题每组一次。固定 Luna 单体用于补充质量和费用参照。复用结果须匹配任务指纹、模型、角色提示、四轮工作流和配置额度，Router 还须匹配候选架构与路由提示。主对照 28 个位置复用 12 个，新增 16 个。固定 Luna 单体复用 3 个，另补 11 个。两档路由策略在扩大任务集前已固定。最终报告按同题配对汇总整体费用、分档费用、通过数及耗时，并单列异常和路由开销。[14 题配置](../../configs/workflow-structure-router-two-tier-mixed.json) · [逐题复用清单](../../artifacts/plan20-two-tier-mixed-preflight-01/coverage.json)

### 简单规则与 LLM Router 离线对照

固定一条关键词规则，只读取需求和验收描述。出现迁移、权限、原子或回滚及其指定英文表达时，使用 Sol 规划加 Luna 自查。其余任务使用 Luna 单体。保留原 LLM Router 的选档，两种方式都按各自选中的架构复用同一份固定组的逐题费用和验收结果。LLM 额外计入已测路由费用。

| 选档方式 | Luna 单体 | Sol 规划 + Luna 自查 | 回放通过 | 回放估算费用 USD |
|---|---:|---:|---:|---:|
| 关键词规则 | 12 | 2 | 14/14 | 0.456769 |
| LLM Router | 9 | 5 | 14/14 | 0.618737 |

规则在 TOMLKit、Packaging 和 TinyDB 三题选了 Luna 单体，LLM 选了 Sol 规划。三题的两个固定组都通过，规则回放总费用低 **26.2%**。两道困难题的选档一致。规则是在前序实验后设定的，每题每个固定架构只有一次存档结果。这里的 14/14 是在同一批存档运行上的回放分数。LLM Router 独立运行仍为 13/14。离线对照共新增 0 次 API 调用。[冻结规则](../../artifacts/plan20-rule-vs-llm-replay-01/policy.json) · [逐题回放](../../artifacts/plan20-rule-vs-llm-replay-01/comparison.md)

**采用决定。** 关键词规则保留为离线成本对照，通用任务分派应由 Agent 根据用户意图、约束和上下文判断。同一个要求可以用不同措辞表达。例如「无需迁移」会命中关键词，「旧版本存下的数据仍然要能读」则可能涉及兼容或迁移，却没有出现「迁移」一词。规则在这 14 题上的回放费用更低，实验没有测量它处理这类措辞变化的能力。采用语义判断是基于日常使用的要求，现有数据未显示 LLM 路由提高了通过率。

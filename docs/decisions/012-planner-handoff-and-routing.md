# 012：规划后交接主会话与 Router 研究

建立：2026-10-27。状态：已实现规划后交接，通过本机固定回复协议检查；尚未运行付费模型比较。

## 背景与假设

[011](011-planner-executor.md) 中四轮消息均先交给 Planner；Sol→Sol 的 Planner 调用量与 Sol 单体完成全部任务相同，另有 Executor 开销。假设减少 Planner 后续参与可能降低总费用，尚无新实验结论。

## 决定与变化

- **本次优先：规划后交接。** 第一轮由 Planner 完成规划；该轮正常结束后，在同一个 OpenCode 会话切换主 Agent 和模型。后三轮全部由 Executor 直接处理并向用户回复，Planner 不再复核、委派或重新介入。
- “一次规划”指一个规划阶段，允许阶段内读取代码及多次模型调用，不等于一次 API 请求。规划失败、额度停止或信息不足时如实停止，不假装已完成交接。
- **后续方向：Router。** 研究根据消息及任务状态选择 Planner／Executor；可比较规则或插件路由与便宜模型作为入口。记录想法，本次不加入 Router，也不增加自动重新规划或失败升级，以隔离交接本身的影响。

## 实现与比较方法

- 新增独立实验策略及配置，保留旧 Planner＋Executor 和单 Agent 对照。两角色均支持 primary；使用适配的角色提示词，Planner 不负责实施轮，Executor 不再等待父 Agent 交接或向其回报。
- 在规划轮完成且会话空闲后，通过 OpenCode 的会话切换能力显式设置 Agent 和模型，保持会话与源码工作区；已有方案通过同一会话历史继续提供，不另加一次模型总结。具体接口须核对本机 2.0.32，不能只改 `default_agent`。
- 沿用角色权限审计及逐轮写入守卫；该策略两角色均禁止委派，规划轮禁止写入。核实切换后的实际 Agent、模型与工具权限，而非仅检查配置文本。
- 固定原四轮提示、任务、模型参数、计价及每例总预算；所有阶段合并计量，按实际角色和轮次记录费用、调用、Token、耗时及切换证据。隐藏验收仅在最后执行，不作为路由输入。

## 验证与未完成项

先核实本机切换协议并做无付费生成的流程检查：同一会话、规划轮无修改、后续只有 Executor、模型正确切换、失败明确停止及计量完整。之后独立配置开展线上比较；每例一次，失败保留，不自动调参重跑。

已新增 `planner_handoff` 策略、独立角色指令和 [六例线上配置](../../configs/workflow-planner-handoff.json)，不改根目录交互配置或旧对照角色。本机 OpenCode 2.0.32 固定回复已验证同会话保留规划历史、后续角色及模型切换、没有子会话、四轮验收通过；不安全权限反例在零生成时拒绝。固定回复仅验证机制，不作为质量或省钱数据。使用说明见 [控制 Agent 行为](../agent-behavior-control.md)。

136 项本地回归通过；同模型交接、不同模型 ID 交接、异常权限拒绝及旧主／子结构检查均通过。证据：[验证汇总](../../artifacts/handoff-verification-20261027.json)、[回归记录](../../artifacts/handoff-regression-final-20261027.txt)。

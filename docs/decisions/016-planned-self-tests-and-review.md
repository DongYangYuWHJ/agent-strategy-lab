# Plan 16：规划测试、执行自测与独立审查

记录日期：2026-11-06。状态：24个预定位置均完成有效验收。最终结果与历史单体对照见文末。

## 决定与职责

用户决定由Planner规划测试、Executor实现并运行、Reviewer验收代码和测试。三者都必须独立对照原始需求，不能把计划清单或自测通过视为完整正确的证明。修正仍由Executor完成，不新增只读复审轮，外部隐藏验收仍为最终裁判。

- Planner：列出重点需求、边界、失败与回归场景，说明预期结果、依据与优先级；只读，不授予写测试或运行自测工具。
- Executor：实现重点unittest自测；可行时先复现后修复；最终修改后重跑自测与公开检查，说明覆盖缺口。只读检查轮不可写。
- Reviewer：读取与重跑自测，检查遗漏、断言、预期值及多余约束；核对结果是否对应当前代码。只读，不写测试或代码。

工具为 `list_tests`、`read_test`、`write_test`、`run_self_tests`。测试独立存放于每次运行的 `self-tests/source`，各轮保存快照；测试运行在当前源码的临时副本，支持stdlib与本项目包，写入只允许 `scratch/`。无任意shell入口；不向子进程传入API密钥，Python审计限制外部文件、网络及子进程。该进程隔离与审计不是针对恶意本机原生代码的OS安全沙箱。隐藏验收器从不复制给自测工作区。单次自测进程30秒保护与模型Token／整段推理限制无关。

空测试、全跳过、提前退出、异常和超时均不作为自测通过。自测结果绑定源码和测试哈希，审查轮不能修改测试；原公开及隐藏验收逻辑不变。

## 对照设计

按用户澄清，比较 **Plan→Execute** 与 **Plan→Execute→Review**，固定Sol Planner、Luna Executor，后者使用Sol Reviewer。

两组共用同一套四轮提示及自测工具：规划、实施、只读检查、修正。PE模型角色顺序为Sol→Luna→Luna→Luna，PER为Sol→Luna→Sol→Luna。PE在第三轮自查，PER独立审查；不通过减少PE交互次数制造差异。Planner和Executor系统提示相同，审查模型与角色一并构成实验处理。

4类原始纯Python开发任务×2结构×3次重复，共24次，seed42打乱。整批5美元，沿用模型档位和无本地Token／调用次数上限。费用含所有阶段与失败，未知用量单列；出错不自动重跑、不调参、不给模型隐藏反馈。新会话与原始任务源码开始，不复用Plan15修正答案。

主要观察最终通过率、全部费用、回归以及自测实际使用和结果新鲜度。这是新版PE与PER比较，不能单独证明提示词或工具各自贡献，也不能与旧版历史批次直接合并证明自测有效；四类开发任务与重复不构成独立留出集。

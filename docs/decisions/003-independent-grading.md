# 003：修复提前退出被判为通过

记录日期：2026-10-21，回顾性补记。状态：修复已实现并验证；不代表已具备完整安全沙箱。

## 观察

原检查程序在评分进程里导入被测代码，并把退出码 0 当作通过。临时复现显示：被测模块只执行 `os._exit(0)`，尚未运行断言，公开检查和最终验收却都可能被判为通过。

这属于验证机制的误判，不能归为候选模型能力问题。仅增加一条“成功”输出也不能证明测试实际完成。

## 改进及方法依据

被测代码放到独立进程中，评分端保留预期结果并核对实际产物。函数任务通过调用协议传回结果；stdio 任务由外部比较 stdout。评分 host 正常完成后才产生与本次调用绑定的完成记录，并核对检查脚本和辅助运行代码的完整性。

验证同时使用正对照与负对照：正确解应通过；未实现、只输出样例答案、打印成功文字和提前退出等行为应被拒绝。两类对照分别帮助发现错误拒绝和错误接受，优于只检查“已有正确样例是否通过”。

## 验证结果和边界

原六题验收审计通过；相关回归覆盖提前退出、错误答案、超时、字符编码和标准输入输出接口。后续扩充的 18 题也完成了独立正负对照审计。

进程分离没有提供 OS 级文件保密、网络隔离或完整资源限制。生成代码仍拥有宿主用户权限，不能把当前结果解释为可防御主动恶意代码。

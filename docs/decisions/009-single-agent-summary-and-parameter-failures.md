## 当前参数明确拦下的两项

### 1. DeepSeek：Dangerous Sugoroku，单次输出额度用尽

- 停止原因：`output_token_limit`。
- 首次请求的输出为 **16384 Token，其中推理也是 16384**；接口返回 `finish_reason=length`，可见正文为空、工具调用为零。
- 输入 1281 Token，实际合计 17665 Token，估算费用 0.019707882 美元。没有写入解法，也没有进入公开或隐藏验收。
- 结论：当前 16k 单次生成额度限制了这次运行，不能记为“完整解法经检验错误”。提高额度或调整推理档位是否有效，仍是待验证假设；本次不改参数、不重跑。

原始证据：[接口响应](../../artifacts/lcb-dev-16k-300s-once-20261021-01/runs/lcb-abc388-f-deepseek-flash-b87dc9a2fcc9/calls/001-response.json)、[运行结果](../../artifacts/lcb-dev-16k-300s-once-20261021-01/runs/lcb-abc388-f-deepseek-flash-b87dc9a2fcc9/result.json)。

### 2. DeepSeek：Hierarchical Majority Vote，下一次调用的预留超过整题额度

- 停止原因：`token_limit`，发生在第 6 次请求发送前；前 5 次调用实际累计 **35416 Token**，费用 0.017458272 美元。
- 待发请求为 51220 字节。DeepSeek 当前按完整请求字节数加 2048 余量估计输入，得到 **53268 Token**；再为最大输出预留 **16384 Token**。

```text
已使用 35416 + 下一次输入估计 53268 + 最大输出 16384
= 105068 > 整题上限 100000
```

因此，这不是实际已经花满 100000 Token，而是保守准入规则不允许继续发请求。53268 是本地估计，不是该次实际输入用量；这次未发出的请求没有供应商 usage。

模型已经写入过代码，中间版本通过公开检查后又改写了一次；最终版本没有进入独立验收，正确性未知。不能把它直接归为模型能力失败，也不能假定增加额度后必然通过。后续需区分“估计偏保守”与“实际需要更多计算”，再决定是否调整总额或估计方法。

原始证据：[事件记录](../../artifacts/lcb-dev-16k-300s-once-20261021-01/runs/lcb-abc391-e-deepseek-flash-2465ca916b85/events.jsonl)（序号 38 为被拦截请求的准备记录）、[运行结果](../../artifacts/lcb-dev-16k-300s-once-20261021-01/runs/lcb-abc391-e-deepseek-flash-2465ca916b85/result.json)、[准入计算逻辑](../../src/agent_lab/accounting.py)。

## 阶段结论与接下来的范围

五模型单 Agent 数据进一步支持了任务集在可执行、可验收和识别部分失败类型方面的有效性。Sol 与 Sonnet 本轮都达到 12/12，现有样本对它们的最终正确率区分有限；每模型每题只有一次，不能建立稳定排名，也不能保证公开题目未出现在模型训练数据中。

接下来优先复核失败、补充有区分度的中等／困难任务，再对少量代表性任务做重复实验观察稳定性与费用波动；保留评估集继续不参与调参。模型职责划分和多 Agent 架构仍是后续需要验证的假设。本次记录没有落实新的参数调整或实验运行。

## 后续观察：DeepSeek 的推理用量与额度敏感性

补记日期：2026-10-23。用户手动完成匹配 Token 计数下的 16k／32k 两组实验，每组只包含 Dangerous Sugoroku 和 Hierarchical Majority Vote，各运行一次。本节补充新证据，保留上文原始批次的参数与判断；本次补记不修改运行参数，也不追加模型调用。

| 观察项 | 16k 输出上限 | 32k 输出上限 |
|---|---|---|
| Hierarchical Majority Vote | 通过，隐藏用例 40/40 | 通过，隐藏用例 40/40 |
| Dangerous Sugoroku | 某次请求输出 16384 Token，全部为推理；未写出解法即截断 | 写出解法，公开用例 3/3；下一次请求被累计预算预留拦下，未进行隐藏验收 |
| 两题累计 Token | 37703 | 71397 |
| 估算费用 USD | 0.025384566 | 0.024945354 |

两组任务、提示词、运行器和限制快照一致，模型配置仅输出上限不同。共 16 次实际生成请求，本地输入 Token 计数与供应商报告全部一致。32k 的 Dangerous Sugoroku 已消耗 54411 Token，下一次输入加余量为 19641，再预留最大输出 32768，合计 106820，超过整题 100000 上限。这里是预留停止，不是实际用量已达上限；公开用例通过不能替代最终验收。

原 12 题批次中，DeepSeek 输出 52891 Token，其中接口报告的推理用量为 46859，约占输出的 88.6%；Luna 对应输出为 18498、推理为 12242。这只说明本任务集和各自配置下 DeepSeek 的推理输出较多，不能把不同模型的 Token 或推理档位当作相同计算单位。累计输入还包含多轮重传的历史，不全是新增思考。缓存与单价也影响费用，因此“Token 较多”不能直接写成“更贵”。

暂定模型特征：**当前配置下，DeepSeek 在部分困难算法题上会产生较多推理输出，对单次输出额度以及多轮累计预算较敏感；提高单次上限能让本次困难题推进到代码和公开检查，但尚未验证最终正确性提升。** 不据此推断所有真实开发任务都具有相同表现，也不据此固定模型职责。

用户同意暂时停止这项额度调参。关于转向 OpenCode 真实开发任务、再比较单 Agent 与协调者＋执行者的建议，仍待讨论确认；本次没有实现新的实验后端或协作策略。现有原生实验已包含多轮模型／工具交互，主要代表边界是独立算法题、完整固定需求和自动验收，尚未覆盖真实仓库上下文、需求澄清与连续开发会话。

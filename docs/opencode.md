# OpenCode 交互入口与实验后端

当前固定 OpenCode **2.0.32**。交互入口保留原有配置；另有已接入任务复制、四轮消息调度、计量网关与独立验收的实验后端，见 [工作流说明](workflow-experiments.md)。公司 GIA 的配置和能力限制仍需在公司环境核实，本地配置不代表可直接导入 GIA。

## 启动

在项目目录的 PowerShell 中运行：

```powershell
.\run-lab.cmd opencode-doctor
.\run-opencode.cmd
```

启动桥接核对版本，从环境变量或 `settings.local.json` 解析 OpenAI、DeepSeek 密钥，仅设置子进程环境，然后打开独立 OpenCode 终端。不会自动提交初始任务，不会写入系统环境变量或把密钥复制到配置文件。直接执行 `opencode` 不会读取我们自定义的 `settings.local.json`，因此应使用项目入口。

`opencode-doctor` 查询模型目录，并启动仅监听本机的临时认证服务，等待角色注册后检查三个角色的模型与模式，随后关闭服务。它可能写入 OpenCode 自身的本地日志／数据库，但不发出生成任务。目录中有模型不代表密钥、额度和实际模型调用已经验证。

公共配置为根目录 `opencode.jsonc`，提示词为 `roles/*.md`。配置中的密钥是环境变量占位符，可以提交 Git；本地 `settings.local.json` 继续忽略。桥接不注入 Claude 密钥，因为这个原型没有使用 Claude 的角色。

## 角色与工具

| 角色 | 模型 | 职责 |
|---|---|---|
| lab-coordinator，默认主角色 | OpenAI Sol | 理解需求、读取代码、交接一个实现任务、核对证据并汇报 |
| lab-worker，子角色 | DeepSeek Flash | 读取和修改任务允许的文件，不再委派 |
| lab-solo，对照主角色 | OpenAI Sol | 独立实现任务，不调用子角色 |

默认流程是开发者对话 → 协调者 → 执行者 → 协调者汇报。协调者不可编辑，执行者和对照角色可编辑；当前仅提供文件工具和协调者提问，默认拒绝 shell、外部目录和其他工具。配置禁止读取本地密钥、`.env` 与实验原始记录，禁止改写角色提示词、OpenCode 配置和现有验收脚本。任务中的其他文件范围约束目前依靠提示词，尚未由隔离任务的精确权限列表强制实现。

每个开发者任务最多一次委派是提示词约束；每角色 steps 仅限制该角色步骤。二者都不是整个会话的费用上限。执行者无法运行检查时必须如实说明，不能凭文字“完成”判定验收通过。当前提示词配置了最小督察行为，没有投票审查或自动升级重规划。

## 原型接入清单与当前对应实现

以下是交互原型原先的接入要求。工作流后端通过专用配置、白名单 MCP、计量网关和会话调度实现这些边界；本文件前面的交互原型不自动获得后端限制。真实验收与计量结果以各次运行报告为准。

1. 每次从冻结任务复制源码，生成仅允许任务文件的 OpenCode 权限；最终验收程序留在源码副本外。
2. 用单 Agent 与协调者＋执行者分别试跑一个小任务，保存角色、真实调用模型、工具轨迹、源码差异和外部检查结果。单次试跑只证明接入是否工作。
3. 枚举主会话与所有子会话，纳入标题、摘要、压缩、重试等额外调用；记录缺失用量，不能默认为零。增加调用前预算控制、全局步骤／时间限制和中断记录后，再接入现有批次账本。
4. 以 `backend=opencode` 单独分组，固定 OpenCode 版本、配置、提示词和任务指纹；原生与 OpenCode 的工具和上下文不同，结果不能直接解释为纯模型能力差异。

现有 `batch` 命令的限制只控制原生 runner，尚不控制交互原型。OpenCode 默认维护任务、模型参数、缓存和网络重试也不能假定与原生适配器相同。正式费用比较应保存实际使用的完整运行配置，并核对供应商账单。

目录副本与文件工具权限不等于 OS 沙箱；OpenCode 进程持有所需 API 密钥。当前仅用于受信任的小型任务。下一阶段先接通独立验收和计量，再增加复杂任务与架构策略。

配置格式依据 [OpenCode V2 配置](https://opencode.ai/v2/docs/config)、[Agent 配置](https://opencode.ai/v2/docs/agents) 和 [API](https://opencode.ai/v2/docs/api)；本机角色加载结果以固定版本的实际检查为准。

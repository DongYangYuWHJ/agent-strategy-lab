# 实验决策与计划变更记录

[English experiment plan and decision history](en/experiment-plan.md)

这里记录实验为什么发生变化：遇到了什么问题、依据是什么、决定怎么调整、已经做到哪里，以及还不能得出什么结论。运行报告回答“发生了什么”，决策记录回答“为什么改、这次学到了什么”。

## 维护约定

- 仅在整体实验计划、方法或架构方向发生实质变化时，新增一篇 `docs/decisions/NNN-主题.md` 并更新索引，例如引入调参集／保留评估集、改变研究目标或采用新的协作架构。不按每次对话更新计划。
- 日常调参（如修改 Token 上限）、常规修复、补充同类任务和进度说明不单独新增决策记录；实际参数与结果由运行配置快照、原始数据和报告保存。只有这些工作导致整体实验方法改变时才记录该决定。
- 每篇至少说明：背景／观察、决定、变化、方法依据、验证证据、实施状态和未完成项。没有验证的设想明确写成假设，不能写成实验结论。
- 区分“已观察到”“已决定但尚未实现”“已实现并验证”。提出更高 Token 额度，不等于已经修改配置或运行实验。
- 历史记录保留当时的依据；后续判断改变时用新记录说明并链接旧记录，不把旧实验重写成成功结果。勘误应明确标注。
- 任务、参数、提示词、框架和计价版本的实际快照仍以各次运行记录为准。决策文档不替代原始证据，也不保存密钥或私有对话。
- 本目录文档可随 Git 分享。部分证据位于本机 `artifacts/`，该目录被 Git 忽略；只克隆仓库时，这些链接可能不可用，因此文档同时保留关键发现与适用范围。

## 调参集为什么借鉴机器学习

机器学习中，在同一批测试样本上反复选超参数，会把测试反馈间接带入选择过程，成绩就可能高估泛化效果。因此，通常把调参使用的验证集与最终测试集分开。[scikit-learn 官方说明](https://scikit-learn.org/stable/modules/cross_validation.html)

我们借鉴的是这项实验原则。目前没有训练或微调模型权重，调整的是输出额度、推理档位、提示词、工具和执行策略，所以更准确的称呼是“开发／调参集”和“保留评估集”，不是模型训练集。

| 本项目名称 | 用途 | 可以根据结果反复调整参数吗？ |
|---|---|---|
| calibration：原六题 | 检查工程流程，复现已经观察到的问题 | 可以；不能再当作未见过的最终评估 |
| development：新增六题 | 探索额度、提示词等设置 | 可以；最终选出的参数仍需在保留集确认 |
| holdout：另外六题 | 参数和方案冻结后，检查能否迁移到其他题 | 不应据此反复调参；否则需补充新的保留任务 |

当前调参配置合并 calibration 与 development，共 12 题；保留配置包含另外 6 题。每个独立分组都有 easy、medium、hard 各两题。这里的 calibration 指工程校准，不是概率置信度校准。

还有两种容易混淆的“隐藏”：

- **每题的隐藏用例**：检查同一道题的解法能否覆盖公开样例之外的输入。
- **整道任务的保留评估集**：检查我们在其他题上选出的参数，能否用于没有拿来反复调参的任务。

两者解决不同层次的问题，需要同时保留。对保留任务做独立验收器的正负对照审计，不等于用候选模型在保留集上的成绩来调参；当前没有进行后者。

当前划分只控制我们的实验反馈。题目公开、全部来自 AtCoder 且数量较少，不能据此保证模型预训练未接触过它们，也不能代表真实仓库开发能力。目前没有实施交叉验证、嵌套交叉验证或严格统计显著性检验。
